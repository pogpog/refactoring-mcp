# Behavioral Design Patterns

 Behavioral design patterns are concerned with algorithms and the assignment of responsibilities between objects. [Chain of ResponsibilityLets you pass requests along a chain of handlers. Upon receiving a request, each handler decides either to process the request or to pass it to the next handler in the chain.](Chain%20Of%20Responsibility.md) [CommandTurns a request into a stand-alone object that contains all information about the request. This transformation lets you pass requests as a method arguments, delay or queue a request's execution, and support undoable operations.](Command.md) [IteratorLets you traverse elements of a collection without exposing its underlying representation (list, stack, tree, etc.).](Iterator.md) [MediatorLets you reduce chaotic dependencies between objects. The pattern restricts direct communications between the objects and forces them to collaborate only via a mediator object.](Mediator.md) [MementoLets you save and restore the previous state of an object without revealing the details of its implementation.](Memento.md) [ObserverLets you define a subscription mechanism to notify multiple objects about any events that happen to the object they're observing.](Observer.md) [StateLets an object alter its behavior when its internal state changes. It appears as if the object changed its class.](State.md) [StrategyLets you define a family of algorithms, put each of them into a separate class, and make their objects interchangeable.](Strategy.md) [Template MethodDefines the skeleton of an algorithm in the superclass but lets subclasses override specific steps of the algorithm without changing its structure.](Template%20Method.md) [VisitorLets you separate algorithms from the objects on which they operate.](Visitor.md)
